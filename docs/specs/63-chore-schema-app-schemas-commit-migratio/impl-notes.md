## 確認事項（人間レビュー要）

### 確認事項 1: Req 1（現行 applicationId schema の git tracking）を本 PR で完結できない

- 本ワーキング環境では Java / Gradle が利用できず、`./gradlew :app:assembleDebug`
  などの KSP ビルドを実行できない（`which java` が `not found`、`./gradlew` 実行は
  JAVA_HOME 不在で失敗）。
- 現状リポジトリ内に `app/schemas/` ディレクトリ自体が存在せず、git 履歴にも schema
  JSON が追加された commit が見当たらないため、**本 PR では add する対象ファイルが
  ない**。
- 既存テスト `app/src/test/java/inc/goodanswers/keynest/data/Migration_1_2_Test.kt`
  のコメントでも「schema JSON files generated by KSP being committed under
  `app/schemas/`」は将来タスクに deferred されている旨が明示されている。
- 対応案: Issue #63 の対応 PR を 2 段階に分けるか、または人間側で 1 回ローカル
  ビルドを走らせ、生成された `v1.json` / `v2.json` を別 commit で追加する運用が
  必要。本 impl-notes 時点では「`.gitignore` + docs」までを先行 commit し、schema
  JSON tracking 自体は人間 / 後続 PR で完結させる前提。
  - 推奨フロー: 本 PR を merge する前に、レビュワー / メンテナが手元で
    `./gradlew :app:assembleDebug` を実行し、生成された
    `app/schemas/inc.goodanswers.keynest.data.KeyNestDatabase/*.json` を本ブランチに
    add → `chore(schemas): track current applicationId schema JSON` で commit して
    から PR を merge する。これで Req 1 が満たされ、Req 4.1 の clean-after-build
    検証も同時に通る。

### 確認事項 2: `room.schemaLocation` のパス整合

- `app/build.gradle.kts` の `ksp { arg("room.schemaLocation", "${projectDir}/schemas") }`
  により、Room の出力先は `app/schemas/inc.goodanswers.keynest.data.KeyNestDatabase/`
  になる想定。これは `KeyNestDatabase.kt` のパッケージ
  (`inc.goodanswers.keynest.data`) と整合している。
- 仮に将来 `KeyNestDatabase` のパッケージを移動する場合、本 Issue の手順では
  applicationId 変更のみを想定しているため、パッケージ移動のケースは別 Issue で
  扱う必要がある（Out of Scope の解釈に含まれる）。

### 確認事項 3: 派生タスク候補（将来 Issue）

- CI 上での Room schema 整合性自動検証は本 Issue の Out of Scope。次フェーズで
  Issue 化する場合、`.github/workflows/` 配下に schema 差分検知ステップを追加する
  形が想定される。
- `app/schemas/inc.goodanswers.keynest.data.KeyNestDatabase/*.json` を実際に追加する
  作業を切り出した子 Issue を立てるかどうかは、本 PR レビュー時に判断する。
